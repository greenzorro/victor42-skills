国内旅行数据源

China Travel Data

当你要查航班、火车、天气或地点，它让 AI 给权威数据，不去网络上随便搜些残缺的过时数据来充数。

When you need flights, trains, weather or places, it hands the agent authoritative data instead of whatever patchy, outdated scraps a web search turns up.

能力

能帮你问什么

  • 「明天杭州飞成都还有票吗，最早一班几点」→ 班次、时刻、票价区间
  • 「周六上海到南京的高铁，下午两点后还有座吗」→ 车次、历时、余票、票价
  • 「下周三丽江会下雨吗」「去年十月大理什么天气」→ 未来预报、历史同期
  • 「西湖到灵隐寺多远，开车要多久」→ 坐标、周边地点、驾车/步行/公交路线

数据从哪来

  • 高德：地址与坐标、周边地点、路线、天气、地图
  • 飞常准：航班计划、中转方案、票价
  • 携程：车次、历时、余票、票价
  • Open-Meteo：天气预报、历史天气
  • 高德与飞常准需要自备 Key（高德控制台申请，飞常准的申请指引随包附带）；携程与 Open-Meteo 开箱即用

它不做什么

  • 不排行程：给数据与规划顺序，不给景点筛选与小时级日程
  • 不抓大众点评 / 小红书：无公开 API，风控严格
  • 不给结论：数据可以给全，取舍由人定

为什么答案靠得住

  • 四类数据都附实测校验：景点坐标必须按地名检索，航班与中转要用不同的三字码，航班列表要自行按时刻排序，报错提示可能指向一个服务端根本不读的请求头
  • 这些规则写在 skill 本体里，Agent 每次调用都照此执行

Capabilities

What you can ask

  • “Any seats on tomorrow's Hangzhou–Chengdu flight, and when is the first one?” → schedules, times, fare ranges
  • “Shanghai–Nanjing high-speed trains on Saturday after 2pm — any seats?” → services, duration, availability, fares
  • “Will it rain in Lijiang next Wednesday?” “What was Dali like last October?” → forecast, same period in past years
  • “How far is Lingyin Temple from West Lake, and how long by car?” → coordinates, nearby places, driving/walking/transit routes

Where the data comes from

  • Amap: addresses and coordinates, nearby places, routes, weather, map tiles
  • Variflight: flight schedules, transfers, fares
  • Ctrip: services, duration, availability, fares
  • Open-Meteo: forecast, historical weather
  • Amap and Variflight need your own key (Amap console; a Variflight application guide ships with the skill); Ctrip and Open-Meteo work as-is

What it doesn't do

  • No itinerary: data and planning order only — no attraction shortlisting, no hour-level schedule
  • No scraping Dianping / Xiaohongshu: no public API, strict anti-bot
  • No verdicts: data can be complete, the trade-offs stay with you

Why the answers hold up

  • All four sources ship verified rules: attraction coordinates need a place-name search, flights and transfers use different three-letter codes, flight lists must be sorted by time, and error text can point at a header the server never reads
  • Those rules live in the skill itself, so the agent follows them on every call
