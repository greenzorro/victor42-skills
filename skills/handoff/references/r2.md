# Object storage (cloud channel)

The cloud channel uses one bucket and one prefix, both configured in `config.md`. This copy ships with `provider = none`; the REST shapes below are what `scripts/r2.py` speaks once you enable it (Cloudflare R2 by default).

## Credentials

Everything lives in the `handoff-config` block of `config.md`: `api_base`, `account_id`, `token` (or the environment variable named by `token_env`), `bucket`, `prefix`.
Auth is `Authorization: Bearer <token>`; R2's REST API does not need S3 keys.

Never write the token into `notes.md`, logs, or any shared/public file.

## Use the script (preferred)

```bash
R2="<this skill>/scripts/r2.py"

python3 "$R2" check                                    # probe: is the cloud channel usable?
python3 "$R2" put notes.md handoff/blog-seo/notes.md   # upload
python3 "$R2" ls  blog-seo                             # list a theme
python3 "$R2" get handoff/blog-seo/notes.md -          # print to stdout
python3 "$R2" rm  blog-seo                             # delete the whole theme
```

The script reads every value from `config.md`; no bucket name is hard-coded. Keys must fall under the configured prefix or the command is refused.
`Content-Type` is set from the file suffix (`.md` → `text/markdown; charset=utf-8`).
Exit codes: `0` ok · `1` failure · `2` cloud disabled in config.

## Raw REST (when the script is unavailable)

Base: `{api_base}/{bucket}/objects`

| Operation | Request |
|-----------|---------|
| List | `GET {Base}?prefix=handoff/<theme>/&per_page=1000` (follow `result_info.cursor` while `is_truncated`) |
| Read | `GET {Base}/<key>` |
| Upload | `PUT {Base}/<key>` + `Content-Type` + `--data-binary @file` |
| Delete | `DELETE {Base}/<key>` |

```bash
curl -s -X PUT -H "Authorization: Bearer ${CF_TOKEN}" \
  -H "Content-Type: text/markdown; charset=utf-8" \
  --data-binary @notes.md \
  "{api_base}/{bucket}/objects/handoff/blog-seo/notes.md"
```

## Probe and troubleshooting

`scripts/r2.py check` performs one read-only LIST and prints a single line. The failure kind tells you what to fix:

| Result | Meaning | Fix |
|--------|---------|-----|
| `cloud ok` | Network, credential and bucket all fine | use the cloud channel |
| `disabled` (exit 2) | `provider = none` | go local; no question needed |
| `config` | `account_id` empty | fill it in `config.md` |
| `auth` | Token revoked, mistyped, or missing permission (Cloudflare signals this with HTTP 400 + code 9106, not 401) | issue a new token with object read/write, verify with `CF_TOKEN=... python3 r2.py check`, then write it into `config.md` |
| `network` | DNS, proxy, or offline | `curl -sI https://api.cloudflare.com`, set `https_proxy` if needed; fully offline → local package |
| `account/bucket` | Wrong account id, or the bucket does not exist (404 + code 7003 / 10006) | check `account_id` and `bucket` |
| `server` | 5xx / 429 from the provider | retry later, don't force writes |
| `api` | Non-JSON body or `success:false` | the printed body usually says why |

Order of work: test with `CF_TOKEN` override first (no file edit) to tell a credential problem from an environment problem; only then edit `config.md`.

## Traps

- **Percent-encode keys** with non-ASCII characters and spaces: `handoff/排错登录` → `handoff/%E6%8E%92%E9%94%99%E7%99%BB%E5%BD%95`. The script handles it; with curl use `jq -rn --arg k "$KEY" '$k|@uri'` or Python's `urllib.parse.quote(key, safe="/")`. Unencoded keys 404.
- **`Content-Type` matters**: a wrong or missing type turns a rendered note into a download.
- **Private buckets have no public URL**: there is no shareable link. The other side needs the same credentials.
- **There is no "delete a folder"**: list the prefix, then delete each object.
- Don't delete the local scratch copy before the upload is verified.
